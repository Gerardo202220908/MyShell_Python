1. Explicacion del Diseno Concurrente

1.1 Arquitectura Bounded-Buffer (Buffer Acotado)

El patron Productor-Consumidor con Buffer Acotado (Bounded-Buffer) es un modelo clasico de concurrencia descrito por Dijkstra y formalizado por Tanenbaum. Resuelve la coordinacion entre procesos que generan y consumen datos a distintas velocidades, compartiendo una region de memoria intermedia de capacidad fija.

CapaComponenteFuncion en el sistema
Buffer circularbuffer[TAMANIO_BUFFER], cabeza/cola/countAlmacen compartido de capacidad maxima 5. Acceso FIFO mediante punteros modulares.
Productores2 hilos POSIX — void *productor()Cada hilo genera 4 items numerados unicamente (id x 100 + i) e inserta en el buffer.
Consumidores3 hilos POSIX — void *consumidor()Cada hilo extrae 4 items del buffer, senalizando espacio disponible tras cada extraccion.

1.2 Los Tres Semaforos del Sistema

/* Inicializacion: los tres semaforos del sistema */
sem_init(&mutex,  0, 1);              /* Binario: cerrojo de exclusion mutua */
sem_init(&vacios, 0, TAMANIO_BUFFER); /* Conteo: ranuras vacias disponibles */
sem_init(&llenos, 0, 0);              /* Conteo: ranuras llenas disponibles */
SemaforoTipoValor inicialInvariante
mutexBinario (0/1)1Solo un hilo accede al buffer a la vez
vaciosConteo [0,N]N=5vacios + llenos = TAMANIO_BUFFER
llenosConteo [0,N]0Refleja elementos consumibles disponibles

1.3 Configuracion del Sistema

#define TAMANIO_BUFFER       5   /* Ranuras del buffer circular          */
#define NUM_PRODUCTORES      2   /* Hilos que insertan items             */
#define NUM_CONSUMIDORES     3   /* Hilos que extraen items              */
#define ITEMS_POR_PRODUCTOR  6   /* Total producido: 2 x 6 = 12 items    */
#define ITEMS_POR_CONSUMIDOR 4   /* Total consumido: 3 x 4 = 12 items    */
Nota de balance y terminacion limpia: Con 2 productores × 6 ítems = 12 ítems producidos y 3 consumidores × 4 ítems = 12 ítems consumidos, la carga está balanceada de forma exacta. Todos los hilos concluyen su ciclo, pthread_join() retorna limpiamente y se garantiza liberación total de recursos sin bloqueos residuales.

2. Diagrama de Estados de Hilos (Tanenbaum)

Segun el modelo de Tanenbaum (Modern Operating Systems, Cap. 2), un hilo puede encontrarse en uno de tres estados fundamentales. El diagrama muestra las transiciones en el contexto del problema Productor-Consumidor:

2.1 Descripcion de Transiciones

TransicionEvento disparadorPrimitiva POSIX
NEW → READYHilo creado, esperando turno de CPUpthread_create()
READY → RUNNINGScheduler del kernel asigna nucleo CPUPreemption del SO
RUNNING → READYQuantum de tiempo agotadoInterrupcion de reloj
RUNNING → BLOCKEDBuffer lleno (prod.) o vacio (cons.)sem_wait()
BLOCKED → READYOtro hilo libera el recurso esperadosem_post()
RUNNING → TERMINATEDHilo completa sus ITEMS_POR_HILO operacionespthread_join()
Clave del diseno: Un hilo Bloqueado no ocupa CPU. Al ejecutar sem_wait(&vacios) con valor 0 (buffer lleno), el hilo productor es suspendido por el kernel, cediendo el procesador. Solo regresa al estado READY cuando un consumidor ejecuta sem_post(&vacios).

3. Demostracion Teorico-Empirica de Ausencia de Deadlocks

3.1 Las Cuatro Condiciones de Coffman

Un interbloqueo (deadlock) ocurre si y solo si se cumplen simultaneamente las cuatro condiciones de Coffman (1971). La estrategia de diseno elimina la condicion de Espera Circular:

Condicion de CoffmanPresente?Analisis en nuestro sistema
Exclusion MutuaSiSolo un hilo accede al buffer a la vez (mutex)
Retencion y EsperaSiUn hilo retiene mutex mientras trabaja en el buffer
No expropiacionSiLos semaforos no son expropiados por el SO
Espera CircularNOEliminada por el orden estricto de adquisicion

3.2 El Orden Estricto: sem_wait(vacios/llenos) ANTES de sem_wait(mutex)

/* PRODUCTOR: orden correcto */
sem_wait(&vacios);    /* 1 Espera espacio libre (puede bloquearse aqui) */
sem_wait(&mutex);     /* 2 Adquiere cerrojo solo si tiene garantia      */
  /* ... seccion critica: insertar en buffer ... */
sem_post(&mutex);     /* Libera cerrojo                                  */
sem_post(&llenos);    /* Senaliza item disponible                        */

/* CONSUMIDOR: orden correcto */
sem_wait(&llenos);    /* 1 Espera item disponible (puede bloquearse aqui)*/
sem_wait(&mutex);     /* 2 Adquiere cerrojo solo si tiene item garantido */
  /* ... seccion critica: extraer del buffer ... */
sem_post(&mutex);     /* Libera cerrojo                                   */
sem_post(&vacios);    /* Senaliza espacio libre                           */

3.3 Analisis del Escenario Critico (Buffer Lleno)

EscenarioCodigo INCORRECTOCodigo CORRECTO
Productor con buffer lleno sem_wait(&mutex) retiene mutex
sem_wait(&vacios) se bloquea
Consumidor no puede entrar: mutex tomado → DEADLOCK		 sem_wait(&vacios) se bloquea SIN mutex
sem_wait(&mutex) solo si hay espacio
Consumidor obtiene mutex libremente → sin deadlock
Por que el orden incorrecto causa Deadlock: Si un productor adquiere mutex primero y luego se bloquea en sem_wait(&vacios) (buffer lleno), ningun consumidor podra adquirir mutex para extraer un elemento. Ambos hilos quedan bloqueados indefinidamente — condicion clasica de espera circular (A espera a B, B espera a A).

5. Conclusiones

Pilar 1 — Multihilo POSIX (6 pts): Los cinco hilos (2 productores + 3 consumidores) se crean con pthread_create() y su terminacion es ordenada mediante pthread_join(). Cada hilo opera de forma independiente y concurrente, compartiendo el espacio de memoria del proceso padre.

Pilar 2 — Exclusion Mutua (8 pts): El semaforo binario mutex (inicializado en 1) garantiza que solo un hilo acceda al buffer circular en cada instante, previniendo condiciones de carrera (race conditions) sobre las variables compartidas buffer[], cabeza, cola y count.

Pilar 3 — Ausencia de Interbloqueos (4 pts): El orden estricto de adquisicion — semaforo de conteo (vacios o llenos) siempre antes del mutex — rompe la condicion de Espera Circular de Coffman, eliminando matematicamente la posibilidad de deadlock.

Resultado verificado empiricamente: El programa concluye en aproximadamente 2-3 segundos con todos los items procesados, el buffer en estado consistente, sin congelamiento y sin corrupcion de indices.
